# قضاء | Qadaa — MVP Android

## ما الذي يعمل في هذه النسخة؟
- تطبيق Android أصلي (Kotlin + Jetpack Compose)، واجهة عربية من اليمين لليسار.
- إدخال إجمالي أيام القضاء، وموعد نهائي من منتقي التاريخ (افتراضيًا: اليوم السابق لرمضان القادم)، واختيار المدينة (13 مدينة مصرية، الافتراضي دمياط).
- **خوارزمية أقصر الأيام** (`domain/Planner.kt`): تمر على كل يوم من اليوم حتى الموعد، تستبعد رمضان والعيدين وأيام التشريق والأيام المكتملة والمستبعدة، ثم ترتب حسب مدة الصيام (الفجر → المغرب) تصاعديًا، والتعادل يُحسم بالتاريخ الأسبق، وتختار أول N يومًا.
- تسجيل يوم كمكتمل (لليوم أو يوم سابق فقط)، واستبعاد يوم لا تستطيع صيامه مع إمكانية إرجاعه، والتراجع عن التسجيل.
- **حفظ دائم** عبر Jetpack DataStore: كل التغييرات تُكتب على القرص فورًا وتبقى بعد إغلاق التطبيق أو إعادة تشغيل الهاتف.

## المواقيت: تقديرية وليست وهمية ولا رسمية
- تُحسب فلكيًا (معادلات NOAA لموقع الشمس) لإحداثيات المدينة المختارة، بطريقة **الهيئة المصرية العامة للمساحة**: الفجر عند انخفاض الشمس 19.5°، والمغرب عند الغروب (−0.833°).
- فرق التوقيت يُؤخذ من قاعدة المناطق الزمنية في الجهاز (`Africa/Cairo`)، فالتوقيت الصيفي (UTC+3) محسوب تلقائيًا.
- لا تُحتسب الارتفاعات ولا دقائق الاحتياط، والخطأ المتوقع دقيقة إلى بضع دقائق. الواجهة تكتب "(تقديري)" بجانب كل وقت.
- التاريخ الهجري من تقويم أم القرى (`java.time.chrono.HijrahDate`)، وقد يختلف يومًا عن إعلان دار الإفتاء المصرية.

## الاختبارات
```bash
./gradlew testDebugUnitTest
```
11 اختبارًا: أن الأيام المختارة هي فعلًا الأقصر (كل يوم مختار ≤ كل يوم غير مختار)، والترتيب، واستبعاد المكتمل والمستبعد ورمضان والأعياد، وحالات الحدود، والموعد الافتراضي، ومقارنة المواقيت بقيم مرجعية للقاهرة شتاءً وصيفًا (±5 دقائق).

## البناء
يتطلب JDK 17+ وAndroid SDK (platform 35، build-tools 35).
```bash
echo "sdk.dir=/path/to/android-sdk" > local.properties
./gradlew assembleRelease   # app/build/outputs/apk/release/app-release.apk
```
نسخة release مصغّرة بـ R8 وموقّعة بمفتاح debug المحلي لتُثبَّت مباشرة. قبل النشر على Google Play استبدله بمفتاح خاص بك.
